# docforge Benchmark 规范（v0.1）

本文件是评测体系的**契约**：指标口径、提交格式、标注协议、数据合规。改动任何一条都必须升数据集版本号（如 `v0.1` → `v0.2`），榜单按版本分列。

## 1. 数据集

| 版本 | 名称 | 性质 | 规模 | 状态 |
|---|---|---|---|---|
| v0.0 | `docforge-zh-synthetic-v0.1` | 程序化合成，GT 精确已知 | 10 样本 | 已发布（随仓库分发） |
| v0.1-rc | `docforge-zh-real-v0.1-rc` | 真实政府公开公文（数字页 + 仿真扫描页） | 7 样本 | 已发布（两轮独立复核一致率 1.0000，第二标注员招募中） |
| v0.1 | `docforge-zh-human-v0.1` | 真实文档人工标注扩容 | 50–100 页 | 标注协议就绪，扩容中 |

真实集 v0.1-rc 的标注方式与边界：GT 文本逐块取自 PDF 文字层并经程序化 QA（归一化后必须能在原文中找到、纯文本页覆盖率 ≥ 0.95）；标题层级、表格跨行列结构、阅读顺序由标注员对照页面渲染图核定；扫描仿真页（整页位图）的 GT 从数字版精确继承。一致性检验已完成两轮：第二轮由同一标注员**仅依据渲染图**独立重标（不同信息源），文本一致率 1.0000、表格/标题结构零分歧（[AGREEMENT.md](../benchmark/data/real-v0.1-rc/AGREEMENT.md)）——注意这是「图文互证 + 转写保真度」的度量，**不能替代双人独立标注**，第二位标注员到位后出对比报告并升 v0.1。

合成集的用途边界：验证评测链路自洽、指标实现回归、引擎冒烟。**合成集数字不构成对真实文档的性能主张**，榜单页对此有显著声明。

真实集的类型配比（目标）：财报（合并单元格表）/ 学术论文（双栏+公式）/ 合同（盖章扫描）/ 教材（多栏图文）/ 扫描公文（红头、骑缝章）。

## 2. 指标口径（确定性指标，无 LLM judge）

四项指标都在**归一化后的提交内容**上计算。归一化规则（`benchmark/normalize.py`，最小化且写死）：

> NFKC → 去软连字符 → 去全部空白 → 小写。markdown 语法剥离不在归一化里做（在引擎适配层显式完成，规则可审计）。

| 指标 | 定义 | 实现 |
|---|---|---|
| 文本 | `1 − CER`，CER = 编辑距离 / GT 归一化长度（封顶 1.0） | 两行滚动 DP |
| 表格 | TEDS：HTML 表解析为标签树，树编辑距离 / max(\|T1\|,\|T2\|)，取 GT 表均值 | 自研 Zhang-Shasha |
| 阅读顺序 | 块对齐后的有序对准确率（相对顺序一致的对数 / 总对数） | 精确匹配 + ≥0.6 贪心模糊对齐 |
| 标题树 | [(level, text)] 建树，同上树编辑距离 | 标签 `L{level}:{text}`，update 代价 0/1 |

### TEDS 实现约定（与 PubTabNet 官方的差异，全部显式）

1. `th` 归一为 `td`（markdown 基线没有表头语义，避免平凡惩罚）；
2. td 内文本归一化后作为单一文本子节点（标签 = `#文本`）；
3. update 代价：标签相同 0；两个文本节点 `1 − (1 − lev/len)`；其余 1；
4. insert/delete 代价 1；相似度负值截断为 0。

### 块对齐规则（阅读顺序指标的前提）

不同引擎切块粒度不同，先对齐再比较顺序：

1. 归一化后**精确相等**的块按下标顺序配对（重复文本块不错位）；
2. 剩余 GT 块按顺序与剩余 pred 块做贪心模糊匹配（`difflib.SequenceMatcher` ratio ≥ 0.6，唯一匹配）；
3. 匹配数 < 2 时该指标记 `null`（不计入均值），报告中显示 `—`。

### 聚合口径

- 每个指标：非 null 样本的算术平均 + 覆盖率（`n/N`）；
- 综合 = 各指标均值的均值（只算有值的指标）；
- **量化数字四要素**：测试集版本 / 样本量 / 对比基线 / 显著性。合成集样本量小，不宣称统计显著性；真实集发布时按类型分层报告并给置信区间。

## 3. 提交格式

一个 JSON 文件，schema 见 `benchmark/schema.py`（JSON Schema draft-07，CI 自动校验）：

```json
{
  "engine": "your-engine-name",
  "dataset": "docforge-zh-human-v0.1",
  "samples": [
    {
      "id": "sample-id",
      "text_blocks": ["标题", "正文……"],          // 阅读顺序；不含表格内容
      "tables": ["<table><tr><td rowspan=\"2\">…"],
      "headings": [[1, "标题"], [2, "小节"]]
    }
  ]
}
```

规则：块粒度自定（对齐规则保证可比）；表格给完整 `<table>` HTML；文本块中不要混入 markdown 语法标记。校验不通过的提交不上榜。

## 4. 标注协议（真实集）

1. **预标注**：`docforge annotate input.pdf --out human/<id>/` 生成 pred.md + GT 模板，标注员在其上修正；
2. **双人独立标注**：A/B 互不可见；表格 HTML、阅读顺序、标题层级全部标注；
3. **一致性检查**：`docforge bench-agree gt.json gt.b.json` 输出逐样本文本一致率（1−CER）与块数差异；≥0.98 视为可发布；
4. **仲裁**：低分样本第三人仲裁，结论写入 `notes.md`；
5. **发布**：样本目录 + manifest + 标注指南随版本 tag 发布。

术语说明：标注一致性常用 Cohen's Kappa，但它适用于**分类标签**；本数据集的 GT 主体是连续文本，因此一致性主指标是文本一致率（1−CER）+ 块数差异，块类型等分类字段引入后再补 Kappa。

## 5. 数据合规

真实集只收录**可再分发**的来源：

- 优先：arXiv / CC 协议论文、政府公开文件、已授权脱敏文档；
- 财报类：上市公司公告为公开信息，但转载条款不一——默认只入库「来源链接 + 文档哈希 + 标注 JSON」，原 PDF 由使用者按链接自取；
- 合同类：使用合成重排版式（保留真实难点特征，不含真实当事人信息）；
- 入库文档一律去除个人敏感信息（身份证号、手机号等做遮盖标注）。

## 6. 防作弊设计

- 提交必须过 JSON Schema；
- 指标全部确定性计算，同输入必得同分；
- 每个数字携带子集/类型标签，禁止跨版本比较；
- 榜单页显著区分合成集与真实集。
